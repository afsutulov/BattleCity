# Battle City

[English](README.md)

Защищайте орла, уничтожайте вражеские танки и пройдите 35 классических этапов.
Играйте в одиночку или вдвоём за одним компьютером, создавайте собственные поля
в режиме Construction. Эта версия воссоздаёт предоставленную Battle City
v1.03 с её пиксельной графикой, картами и звуками.

**Вся игровая логика выполняется на Go.** Для запуска не используются и не нужны
эмулятор Mega Drive, ROM, программа картриджа, интерпретатор 68000/Z80 или прошивка
консоли. Ebitengine отвечает за окно, ввод, вывод изображения и звука.

## Возможности

- 35 исходных этапов, один или два игрока, редактор Construction.
- Движение, ИИ противников, появление танков, снаряды, столкновения, разрушение стен, улучшения, бонусы, очки и переходы между экранами реализованы на Go.
- Исходная графика преобразована в PNG, карты — в JSON, звуки — в стереофонический PCM WAV.
- Изображение 256×224, исходный растровый шрифт и масштабирование без сглаживания.
- Клавиатура и стандартные геймпады; режимы 60 и 50 обновлений в секунду.
- Сохранение и загрузка, автоматическое сохранение рекорда, полный экран и отключение звука.
- Английские подсказки STAGE, собственная иконка и запуск сразу с меню игры.

## Запуск

Для Linux нужна графическая сессия с X11/XWayland, OpenGL и PulseAudio либо ALSA.
Приложения macOS рассчитаны на macOS 12 и новее. Они не прошли нотариализацию
Apple; сборщик поддерживает локальную подпись ad-hoc. Файлы Windows и macOS
скомпилированы кросс-компилятором; проверка на физических устройствах с этими
системами ещё не выполнена.

### Управление

| Действие | Игрок 1 | Игрок 2 |
|---|---|---|
| Движение | Стрелки | W A S D |
| Огонь — кнопки A / B / C | Z / X / C; пробел также соответствует B | G / H / J |
| Старт / пауза в игре | Enter | Tab |

На экране **STAGE**: **Enter** — выбрать, **пробел / X** — следующий этап,
**C** — предыдущий. В **Construction** перемещайте курсор стрелками и размещайте
блоки пробелом / X или C. Повторное нажатие на том же месте переключает тип блока
вперёд или назад. **Enter** принимает карту и возвращает в меню; карта используется
на следующем этапе. На геймпаде используются крестовина / левый стик, три кнопки
West/South/East и Start.

| Клавиша | Действие |
|---|---|
| Esc | Выход из главного меню; возврат в главное меню со всех остальных экранов |
| F1 | Подсказка по управлению |
| F5 / F9 | Сохранить / загрузить |
| F8 | Перезапустить игру |
| F11 / Alt+Enter | Полноэкранный режим |
| M | Выключить / включить звук |
| F10 | Выход |

### Параметры и сохранения

```sh
./bin/BattleCityMD-linux-amd64 -fullscreen
./bin/BattleCityMD-linux-amd64 -pal
./bin/BattleCityMD-linux-amd64 -aspect pixel -scale 4
```

Параметры одинаковы на всех платформах. По умолчанию: 60 обновлений в секунду,
пропорции телевизора 4:3 и начальный масштаб 3. `-pal` включает 50 обновлений
в секунду; `-aspect pixel` — квадратные пиксели и целочисленный масштаб;
`-scale 1..6` задаёт начальный размер окна; `-mute` отключает звук при запуске.
На macOS передавайте параметры через `open -a <путь-к-приложению> --args ...`
либо запускайте исполняемый файл из `Contents/MacOS/`.

Рекорд и сохранения JSON находятся в каталоге `BattleCityMD-Go` внутри каталога
настроек пользователя: `%APPDATA%` в Windows, `$XDG_CONFIG_HOME` либо `~/.config`
в Linux, `~/Library/Application Support` в macOS. Рекорд от 0.1.x сохраняется.
Состояния эмулятора от 0.1.x несовместимы с нативной версией. Для режимов 50 и
60 Гц используются отдельные слоты сохранения.

## Сборка

Нужен **Go 1.25.7+**. Все команды выполняются из корня проекта, где лежит
`main.go`. Зависимости управляются Go modules; vendor и отчётов проверки в архиве нет.

```sh
go mod download
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o BattleCityMD .
```

Windows PowerShell:

```powershell
$env:CGO_ENABLED="0"
go build -trimpath -ldflags="-s -w -H=windowsgui" -o BattleCityMD.exe .
```

Примеры кросс-компиляции:

```sh
CGO_ENABLED=0 GOOS=windows GOARCH=arm64 go build -trimpath -ldflags="-s -w -H=windowsgui" -o bin/BattleCityMD-windows-arm64.exe .
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags="-s -w" -o bin/BattleCityMD-linux-arm64 .
```

Сборка приложений macOS из Windows, Linux или macOS:

```sh
go run build_macos.go
# Только одна архитектура:
go run build_macos.go -arch amd64
go run build_macos.go -arch arm64
```

Сборщик использует Go для текущего компьютера, задаёт платформу дочерним сборкам
и формирует два `.app` с ICNS и Info.plist. При запуске на macOS с доступной
`codesign` применяется подпись ad-hoc. Компилятор C и Xcode для компиляции не нужны.
Линкер Go подписывает код ARM64 Mach-O.

Ресурсы Windows с иконкой включены для обеих архитектур. После изменения ICO:

```sh
go run github.com/akavel/rsrc@v0.10.2 -arch amd64 -ico assets/icon.ico -o icon_windows_amd64.syso
go run github.com/akavel/rsrc@v0.10.2 -arch arm64 -ico assets/icon.ico -o icon_windows_arm64.syso
```

## Устройство и соответствие исходной игре

`internal/game` содержит симуляцию и рисование PNG; `internal/audioqueue`
воспроизводит WAV; `internal/storage` сохраняет данные. Ресурсы встраиваются при
компиляции, поэтому готовому приложению не нужны отдельные файлы данных.

Исходная программа использовалась только вне готовой игры: для дизассемблирования,
конвертации ресурсов и сравнения кадров и состояний. Проверены загрузка и 100
тактов каждого из 35 этапов, более длинные игровые сценарии, все шесть бонусов,
лёд, PAL с паузой, продолжение после загрузки и отдельные попиксельные кадры.
Такая проверка не доказывает совпадение во всех возможных ситуациях. Аппаратный
источник случайности заменён счётчиком и начальным значением на Go; аналоговое
изображение и звук, а также аппаратные ограничения числа спрайтов не воспроизводятся.
Задержки ввода и звука зависят и от современного компьютера.
